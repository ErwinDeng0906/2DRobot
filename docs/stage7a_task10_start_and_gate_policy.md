# Stage 7A Task10 起点与安全门策略

## 1. 起点不是“必须等于 P22”

Task10 的目标是验证吸盘从 P22 附近的偏置位置向 P22 槽中心移动，因此不应要求
J1/J2/J3/J4 与 `P22 float` 示教值逐轴相等。正式运行只要求当前状态满足：

- 目标为 P22，且当前安装的 Stage5 模型批准 P22；
- 当前 world XY 位于 Stage5 已验证的局部域；
- J3 和绝对 Rz 与 Stage5 标定条件一致；
- 五帧视觉、机械臂静止性、控制器状态和后续运动学审核通过；
- 当前点、候选终点以及控制器逐轴执行的中间状态都不越出局部域。

当前正式 Jacobian 的 `offset_extent_mm=2.0`，Task10 保留 0.20 mm 边界，因此实际允许的
起点和终点为 Stage5 锚点每个 world 轴 `±1.80 mm`。这已经允许从偏置点开始，不等于只
能在精确 P22 起点运行。

## 2. robot_state_freshness

当前记录值是：

```text
照片保存完成时间 - 对应 record_point 的机械臂状态记录时间
```

它是“状态与图像配对延迟”的保守上界，不是控制器是否在线，也不是运动下发前最后一次
状态读取。DirectShow 快照会主动读取多帧以清空缓存，再保存 JPEG；实测静止运行的五帧
延迟为 0.254–0.296 s，而五帧 XY 和四个关节的变化均为零。因此阈值由 0.25 s 调整为
0.50 s，但该门不删除。

运动前仍必须另外通过：

- `robot_stationary_window`；
- `measurement_matches_request_state`；
- ActionWorker 在人员确认后的全新控制器读取；
- 状态漂移、J3、Rz、FK、局部域和逐轴瞬态的独立复核。

## 3. operator_consent

`operator_consent` 表示人员是否明确点击“确认执行一次 XY 修正”。它不是视觉或控制器
故障，确认前应显示为 `PENDING`，而不是 `FAIL`。后端仍保持默认 false；只有人员点击
确认后才重新构造正式提案并令该门 PASS。关闭弹窗、按 Enter 或点击“不运动”都不会
下发运动。

## 4. J4 的 Rz 预补偿与分离门限

普通 World-XY 点动会改变 J1/J2，但控制器不会自动同步修改 J4，因此绝对角度

\[
R_z=J1+J2+J4-90^\circ
\]

可能偏离 Task9 标定值。Task10 在人员确认同一个 Stage7A 提案之后按以下顺序执行：

1. 在当前 XY 和 J3 不变时计算
   \(J4_{pre}=Rz_{cal}-J1-J2+90^\circ\)；
2. 先执行一个仅改变 J4 的预补偿目标；
3. 回读关节和控制器安全状态，确认预补偿到位；
4. 从预补偿后的真实状态重新审核最终 XY 目标；
5. 再执行 J1 → J2 → J3 → 最终 J4 的 XY 修正。

预补偿和 XY 修正共享同一次明确人工授权，弹窗必须显示 J4 当前值、预补偿目标和
\(\Delta J4\)，`points.json` 保存两段运动及中间状态。任一段失败时都不会继续执行下一段。

三个不同含义的 Rz 门不再共用一个阈值：

- 起点相对标定 Rz：`≤0.20°`，允许普通点动留下的小偏差；
- 最终目标相对标定 Rz：`≤0.15°`；
- J4 预补偿完成后的逐轴瞬时 Rz 偏差：`≤0.30°`。

这不是删除 Rz 保护，而是把起点容差、最终精度和短暂运动过程分别约束。

## 5. 门的分级

### 必须保留的运动阻断门

- 控制器连接、使能、空闲、无报警、无硬/软急停；
- 最终人工确认；
- 相机帧新鲜、测量 ID 唯一、机器人在采样窗口内静止；
- Stage3、目标 P22、Stage5 hash 与模型质量；
- 图像测量与运动请求所绑定的机械臂状态一致；
- 当前点、预计终点及逐轴中间状态位于已验证局部域；
- 固定 J3/Rz、IK 可达、FK 闭合、目标与显示修正一致；
- 单步长度、逐轴分量和控制器逐轴执行瞬态限制；
- 人员确认后重新读取状态、检查提案年龄和状态漂移。

### 可以在 UI 合并或隐藏、但无需删除计算的项目

- `requested_frame_count` 可与 `minimum_accepted_frames`、`unique_measurement_ids`
  合并显示为“采样窗口”；
- `local_domain_definition` 是模型加载时的 schema/数值校验，可在 UI 折叠；
- proposal 与 planner 重复执行的域、步长和 Rz 检查可合并显示，但后端应继续双重检查；
- 运动后的 response gates 只决定本次验证是否成功，不会授权第二次运动。

`predicted_model_response` 和 `full_cancellation_within_measured_scale` 主要防止错误方向或把
大异常误差硬截成一个小步，碰撞风险较低，但目前不建议删除。它们正常时不会造成操作负担，
且能尽早暴露符号错误、错误目标或模型外推。

## 6. 为什么不能直接把 2 mm 改为 10×10 mm

若“10×10 mm”表示以 P22 为中心的每轴 `±5 mm`，现有 Task9 数据没有覆盖该区域。直接
把 JSON 或代码中的 2 改成 5，只会关闭模型有效性保护，不能证明同一个 Jacobian 在外推
区域仍然正确。

扩域应先完成新的 Stage5 标定/验证：

1. 在每轴 `±5 mm` 范围采样，建议至少使用 5×5 网格，而不是只采九个边界点；
2. 每个位置采多帧并继续使用 Stage3、离群点和命令跟踪门；
3. 用未参与拟合的留出点验证 10×10 mm 内的预测误差；
4. 若单一线性 Jacobian 在边缘残差过大，改为多个局部 Jacobian 或 Jacobian field；
5. 只有扩域质量门通过后，正式模型才写入 `offset_extent_mm=5.0`，Task10 再读取该范围。

Stage7A 仍是单步验证，当前每次最多移动 0.25 mm。即使将来批准 10×10 mm，它也不会从
5 mm 外一次回到 P22；多步收敛属于后续 Stage7B/Stage8 闭环状态机。
